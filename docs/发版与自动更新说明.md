# xHR Launcher 发版与自动更新说明

## 一、整体链路

安装包与物料包分离：壳子本体随 NSIS 安装包，各子程序员工本体作为独立物料包按需下载。

```
打 tag vX.Y.Z
   │
   ▼
GitHub Actions（windows-latest）
   ├─ 拉取匹配版本物料（物料仓 Release）
   ├─ dotnet publish + ISCC：安装包 xHR_<版本>_win-x64-setup.exe
   │   + 物料包 material_<id>_<版本>.zip
   ├─ ① 物料包 + materials.json 挂 GitHub Release（物料体积大，不走 Gitee）
   ├─ ② 回填 materials.json 各物料 package_url 为 GitHub 物料直链，补挂回 GitHub
   ├─ ③ 建/取 Gitee 同 tag Release
   ├─ ④ 回填 latest.json 的 package_url 为 Gitee 安装包直链
   └─ ⑤ 安装包 + latest.json + sha256 挂 Gitee Release；latest.json 补挂回 GitHub

客户端（xHR.exe，per-user 安装于 %LOCALAPPDATA%\Programs\x.HR）
   ├─ 壳子更新：启动/手动检查 → 带 JWT 拉 {api_base_url}/api/version/all 的 lite 渠道 → 版本比对 → 推荐更新
   │   按 download_url 下载安装包 → 静默拉起 Setup /S → 退出
   │   → 安装器强杀旧进程（员工由 JobObject 连坐清理）→ 替换文件（用户生成的 config.json 等不动）→ 自动重启新版
   └─ 物料下载：拉 materials.json → 卡片显示“待下载”→ 点下载 → 校验解压到
       %APPDATA%\x.HR\materials\<物料id>\ → 就位后“开始工作”
```

- **三渠道分离**：后端 `version.json` 按 `android` / `desktop` / `lite` 独立管理。**壳子走 `lite` 渠道**，完整版客户端（Electron）走 `desktop` 渠道，互不干扰、不再串包。
- 后台上传壳子包时**渠道必须选 lite**，文件会被重命名为 `app-lite-<版本>.exe`，`download_url` 由后端自动生成；lite 渠道不提供哈希，客户端仅校验下载完整性。

- **安装包走 Gitee**：体积小（不含物料），国内更新稳定；物料包走 GitHub Release（体积大，受 Gitee 100MB 附件上限限制）。
- 壳子更新为**推荐式**：检测到新版本每次启动弹窗提示，可稍后再说，不强制拦截。
- 物料为**按需下载**：首次点用对应员工时才下载，下载后缓存在本地物料目录，覆盖更新壳子不丢物料。

## 二、产物命名

| 项 | 规则 | 托管 |
|---|---|---|
| 主程序 exe | `xHR.exe`（程序集名 `xHR`，产品名仍显示 x.HR） | 安装包内 |
| 安装包 | `xHR_<版本>_win-x64-setup.exe`（NSIS，per-user 免 UAC，仅壳子，自动更新通道用） | Gitee Release（小附件） |
| 全量安装包 | `xHR_<版本>_full_win-x64-setup.exe`（壳子 + 内置员工物料，新用户首装免下载物料；`publish.ps1 -WithMaterials` 生成） | GitHub Release（体积超 Gitee 100MB 上限） |
| 安装包校验 | `xHR_<版本>_win-x64-setup.exe.sha256` | Gitee Release |
| 物料包 | `material_<物料id>_<物料版本>.zip` | GitHub Release |
| 物料包校验 | `material_<物料id>_<物料版本>.zip.sha256` | GitHub Release |
| 壳子更新清单 | `latest.json` | 双端 Release 附件 |
| 物料清单 | `materials.json` | GitHub Release |
| 版本文件 | 包内 `version.json`（`launcher_version` 供本地比对） | 安装包内 |

## 三、GitHub 仓库配置（Settings → Secrets and variables → Actions）

### Secrets

| 名称 | 说明 |
|---|---|
| `GITEE_TOKEN` | Gitee 私人令牌，需勾选仓库 Release 读写权限 |
| `MATERIAL_TOKEN` | 物料仓私有时填只读 PAT；物料仓公开可留空（回退 `GITHUB_TOKEN`） |

### Variables

| 名称 | 示例 | 说明 |
|---|---|---|
| `GITEE_REPO` | `ink-sparrow-pouring-rain/xhr-launcher` | Gitee 仓库 `owner/repo` |
| `GITEE_OWNER` | `ink-sparrow-pouring-rain` | Gitee 用户名/组织名，拼下载直链用 |
| `MATERIAL_REPO` | `Communist-t/xhr-materials` | 物料仓，默认已填 |

## 四、清单字段结构

### 壳子更新清单：后端 `/api/version/all` 的 lite 渠道（JWT 鉴权，登录态即可）

壳子读取其中的 lite 渠道：

```json
{
  "lite": {
    "version": "1.0.5",
    "latest_version": "1.0.5",
    "release_date": "2026-11-20",
    "changelog": ["本次更新说明"],
    "download_url": "/uploads/software/app-lite-1.0.5.exe"
  }
}
```

- 版本比对用 `latest_version`（缺失回退 `version`）；`download_url` 为相对路径时拼 `{api_base_url}` 前缀；lite 渠道无哈希字段，下载后仅校验非空；
- `desktop` 渠道（latest.yml / sha512）归完整版客户端（Electron）与壳子的"完整版"安装卡片使用，壳子自身更新不读它。

### materials.json（物料清单）

```json
{
  "material_version": "rpa-matrix-1.0.0",
  "materials": [
    {
      "material_id": "wechat-rpa",
      "material_version": "rpa-matrix-1.0.0",
      "package_url": "https://github.com/<owner>/<repo>/releases/download/v0.1.1/material_wechat-rpa_rpa-matrix-1.0.0.zip",
      "sha256": "小写十六进制",
      "size": 102900000,
      "entry_exe": "runtime\\python\\pythonw.exe",
      "entry_args": "gui.py",
      "work_dir": "runtime"
    },
    {
      "material_id": "matrix-video",
      "material_version": "rpa-matrix-1.0.0",
      "package_url": "https://github.com/<owner>/<repo>/releases/download/v0.1.1/material_matrix-video_rpa-matrix-1.0.0.zip",
      "sha256": "小写十六进制",
      "size": 294600000,
      "entry_exe": "matrixmedia.exe",
      "entry_args": "",
      "work_dir": ""
    }
  ]
}
```

- `entry_exe` / `entry_args` / `work_dir`：相对物料解压根目录，启动时由 `MaterialService` 解析；
- `package_url`：流水线回填；`sha256` 下载后校验，损坏/篡改则中止物料安装。

## 五、客户端配置

程序目录 `config.json`：

```json
{
  "api_base_url": "http://saas-ai.cn:8080",
  "update_manifest_url": "",
  "material_manifest_url": "",
  "apps": []
}
```

- `update_manifest_url` 留空时默认请求 `{api_base_url}/api/version/all` 的 lite 渠道；仅独立测试源才填覆盖值；
- `material_manifest_url` 留空时默认请求 `{api_base_url}/api/launcher/materials`；
- 物料走 Release 附件分发时，把对应清单直链填入即可，不需要后端接口。

## 六、本地物料目录

- 物料解压根目录：`%APPDATA%\x.HR\materials\<物料id>\`；
- 下载暂存：`%APPDATA%\x.HR\material-download\`（zip 解压后清理）；
- 物料与壳程序目录分离：覆盖更新壳子、重装壳子都不会清掉已下载物料。

## 七、发版操作步骤

1. 更新 `build/version.json`：
   - `launcher_version` 改为新版本（如 `0.1.1`）；
   - `runtime_material_version` 确认与物料仓最新 tag 一致。
2. 提交源码并推送 main：
   ```powershell
   git add .
   git commit -m "release: 0.1.1"
   git push origin main
   ```
3. 打 tag 并推送，触发流水线：
   ```powershell
   git tag v0.1.1
   git push origin v0.1.1
   ```
4. 在 GitHub Actions 查看 `build-release` 运行结果；
5. 核对：GitHub Release 有物料包 + `materials.json`；Gitee Release 有壳包 + `latest.json` + sha256；
6. 客户端启动后点"检查更新"验证壳子比对；点对应员工"下载"验证物料按需下载链路。

## 八、版本对应规则

- 主仓 tag `v0.1.1` ↔ `launcher_version=0.1.1`；
- 物料 tag `rpa-matrix-1.0.0` ↔ `runtime_material_version`；
- 子程序单独升级：先给物料仓打新 tag，再回主仓更新 `version.json` 的物料版本号。

## 九、回滚

- **壳子回滚**：在 Gitee/GitHub Release 找到上一个版本 tag，运行对应旧版 `xHR_<旧版本>_win-x64-setup.exe` 覆盖安装（NSIS 按安装目录覆盖文件，直接降级替换，config.json 与 %APPDATA% 数据不受影响）；
- **物料回滚**：删除本地 `%APPDATA%\x.HR\materials\<物料id>\`，重新从旧版物料清单下载；
- **清单回滚**：把 `latest.json` / `materials.json` 的版本与直链指回上一个稳定包，重新上传到 Release 附件；
- **流水线失败**：旧版本客户端不受影响；更新暂存目录下次启动自动清理。

## 十、注意事项

1. Gitee 仓库需先建好同名空仓，令牌要有该仓 Release 权限；
2. 安装包脚本为 `installer\xhr.nsi`，升级/卸载以注册表键 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\xHR Launcher` 匹配，`InstallDir` 与键名一经发布不可更改；NSIS 只覆盖包内文件，用户运行期生成的 `config.json` 等升级后原样保留；安装位置固定 `%LOCALAPPDATA%\Programs\x.HR`（per-user，免 UAC）；
3. 全量包与轻量包是同一应用（同安装目录、同卸载注册键）：先装全量包的用户，后续自动更新走轻量包，NSIS 只覆盖壳子文件，`apps\`、`appr\` 物料原样保留；
4. Gitee 个人社区版附件单文件上限 100MB，安装包不含物料、正常远低于上限，若逼近需检查是否有物料混进 publish 输出；大体积物料包不上 Gitee，超 GitHub 单包限制时改走对象存储并在 `materials.json` 填对象存储直链；
5. 物料仓目前仍在 GitHub，物料如需迁 Gitee，需同步调整流水线物料下载步骤；
6. 物料包解压后必须是物料根目录内容（入口 exe/脚本 + 运行时 + 资源），不能多套一层文件夹。
